## 先说场景

统一网关已经就位：主站用宿主机静态目录（如 `/opt/nginx-gateway/html`），子域按需反代容器。接下来是「代码怎么变成线上页面」。

典型对象：

- VuePress / VitePress / Hugo / 纯前端 SPA 的 **build 产物**
- 发布目标：主站目录，或子域后面的静态容器 / 另一目录

本文不绑定某一业务仓库名，用「文档站项目」泛指；命令按本地 Linux / macOS + 一台 Debian 云主机来写。

## 构建产物在哪

以 VuePress 为例（其它工具同理，只换输出目录）：

```bash
cd /path/to/your-docs
pnpm install          # 或 npm / yarn
pnpm docs:build       # 脚本名以 package.json 为准
```

常见输出：

| 工具 | 默认可参考路径 |
| --- | --- |
| VuePress | `docs/.vuepress/dist/` |
| VitePress | `docs/.vitepress/dist/` 或项目配置的 `outDir` |
| Vite SPA | `dist/` |
| Hugo | `public/` |

发布时同步的是 **构建结果**，不是源码仓库整棵树。

环境变量（如搜索服务的 App ID）应在 **构建机** 注入；不要把密钥写进将要公开的仓库。静态托管场景下，Search-Only Key 若必须打进前端包，仍建议用 CI Secret / 本机 `.env`（且 `.env` 已 gitignore）。

## 方式一：本机构建 + rsync（最常用）

适合：本机 Node 环境齐、服务器只跑 Nginx。

```bash
# 本机
cd /path/to/your-docs
pnpm install
pnpm docs:build

# 同步到服务器主站目录（--delete 会删掉远端多余文件，慎用）
rsync -avz --delete \
  docs/.vuepress/dist/ \
  deploy@YOUR_SERVER:/opt/nginx-gateway/html/
```

`YOUR_SERVER` 可换成 IP 或 SSH Host。首次建议先不加 `--delete`，确认无误再开。

没有 `rsync` 时：

```bash
cd docs/.vuepress/dist
tar czf /tmp/site-dist.tar.gz .
scp /tmp/site-dist.tar.gz deploy@YOUR_SERVER:/tmp/

# 服务器
mkdir -p /opt/nginx-gateway/html
rm -rf /opt/nginx-gateway/html/*
tar xzf /tmp/site-dist.tar.gz -C /opt/nginx-gateway/html
```

静态文件经卷挂载进 Nginx，**一般不必重启容器**；浏览器强刷即可。

```bash
curl -sSI https://example.com/ | head
# 期望 200；也可抽查某个新页面路径
```

### 发到子域

若子域反代的是**另一个静态目录**（再建一个挂载）或**静态文件容器**：

- 目录方案：rsync 到该目录，子域 `root` 指过去  
- 容器方案：构建镜像推仓库，服务器 `docker pull && docker run/restart`，网关 `proxy_pass` 已指向该容器名  

主站与子域不要混用同一发布目录，除非你明确要「一个产物多个域名」。

## 方式二：服务器上拉取构建

适合：本机不方便装依赖，或希望与线上 Node 版本一致。要求服务器有足够内存（VuePress 等构建偏吃 RAM）。

```bash
# 服务器（一次性）
cd /opt/apps
git clone git@github.com:YOUR_ORG/YOUR_DOCS.git
# 安装 Node（nvm / 发行版包 / 官方二进制）与 pnpm

# 每次发布
cd /opt/apps/YOUR_DOCS
git pull --ff-only
pnpm install --frozen-lockfile
pnpm docs:build
rsync -a --delete docs/.vuepress/dist/ /opt/nginx-gateway/html/
```

用 deploy 专用 SSH Key，权限收窄到该仓库即可。

## 方式三：持续部署（GitHub Actions 示例）

目标：`main` 推送后自动构建，并用 SSH/rsync 发到服务器。密钥放在仓库 Secrets，不要写进 YAML。

### 仓库 Secrets（示例）

| Secret | 含义 |
| --- | --- |
| `DEPLOY_HOST` | 服务器主机名或 IP |
| `DEPLOY_USER` | SSH 用户 |
| `DEPLOY_SSH_KEY` | 私钥全文 |
| `DEPLOY_PATH` | 远端目录，如 `/opt/nginx-gateway/html` |
| （可选）`DOCSEARCH_*` | 构建期环境变量 |

服务器侧：为该公钥建用户，目录可写；可用 `rrsync` 或强制命令限制只允许 rsync 到指定路径。

### Workflow 骨架

路径：`.github/workflows/deploy-docs.yml`

```yaml
name: Deploy docs

on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: Install & build
        env:
          # 按需取消注释
          # DOCSEARCH_APP_ID: ${{ secrets.DOCSEARCH_APP_ID }}
          # DOCSEARCH_API_KEY: ${{ secrets.DOCSEARCH_API_KEY }}
          # DOCSEARCH_INDEX_NAME: ${{ secrets.DOCSEARCH_INDEX_NAME }}
        run: |
          pnpm install --frozen-lockfile
          pnpm docs:build

      - name: Setup SSH
        run: |
          mkdir -p ~/.ssh
          echo "${{ secrets.DEPLOY_SSH_KEY }}" > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519
          ssh-keyscan -H "${{ secrets.DEPLOY_HOST }}" >> ~/.ssh/known_hosts

      - name: Rsync to server
        run: |
          rsync -avz --delete \
            docs/.vuepress/dist/ \
            "${{ secrets.DEPLOY_USER }}@${{ secrets.DEPLOY_HOST }}:${{ secrets.DEPLOY_PATH }}/"
```

要点：

1. **只同步 dist**，不要把 `node_modules` 打上服务器  
2. `workflow_dispatch` 方便手动重发  
3. 构建失败则不会 rsync，避免半套文件覆盖生产（若需更稳，可先传到 `/tmp` 再服务器端原子切换）  

### 更稳的「原子发布」（可选）

```bash
# CI 传到服务器临时目录后，SSH 执行：
RELEASE=/opt/nginx-gateway/releases/$(date +%Y%m%d%H%M%S)
mkdir -p "$RELEASE"
# 解压或 rsync 到 $RELEASE
ln -sfn "$RELEASE" /opt/nginx-gateway/html-current
# Nginx root 指向 html-current，或再 ln 到 html
```

回滚 = 把符号链接指回上一份 release。

## 发布检查清单

1. 构建日志无报错，`dist/index.html` 存在  
2. rsync / 解压路径正确，权限可读（Nginx 容器以非 root 读挂载时注意目录 `o+x`、文件可读）  
3. `curl -sSI https://example.com/` 为 200  
4. 抽查一篇新文章或带 hash 的资源 URL  
5. 若开了 CDN：按需刷新缓存  

## 和网关、证书的关系

```text
git push → CI 构建 dist → rsync 到 html/
                              │
                              ▼
                     nginx-gateway 直接 root 该目录
                              │
                              ▼
                     HTTPS（证书篇）对外提供
```

- 改的是静态文件：通常 **不用** reload Nginx  
- 改的是 `conf.d` 或证书：需要 `nginx -t && nginx -s reload`  
- 子域反代容器：发版可能是 `docker pull` + 重建容器，与主站 rsync 是两条线  

## 小结

| 方式 | 适用 |
| --- | --- |
| 本机 build + rsync | 个人站、改完即发，最简单 |
| 服务器 git pull + build | 本机环境不一致、或无 CI 时 |
| GitHub Actions + rsync | 持续部署；密钥进 Secrets |

主站静态目录 + 统一网关 + 自动 HTTPS，足够覆盖多数「文档站 / 个人站」场景；带 API 的子域把前端当静态或前端容器、API 另反代即可，发布流水线可以分开。
