## 先说场景

统一入口已经用 Docker Nginx 占住 80/443 后，下一步是 HTTPS。目标通常是：

- 浏览器信任的证书（不是自签）
- 证书文件能被**容器内**的 Nginx 读到  
- 到期前自动续期，续完自动 `reload`

本文以 **Let’s Encrypt + Certbot** 为例，域名写成 `example.com`，路径写成 `/opt/nginx-gateway`，按自己的机器替换即可。

## 申请前检查清单

1. **DNS**：`example.com`（及需要的 `www`）A 记录已指向本机公网 IP，等待生效  
2. **80 端口**：公网可访问到本机 Nginx（安全组 / 防火墙放行）  
3. **HTTP 校验路径**：Nginx 对 `/.well-known/acme-challenge/` 指到挂载的 `html` 目录（见网关篇主站配置）  
4. **不要**在校验期间用另一套进程抢占 80

自检：

```bash
dig +short example.com
curl -sSI http://example.com/ | head
# 应能打到你的 Nginx（301 到 HTTPS 也可以；webroot 校验走的是 /.well-known/）
```

## 怎么申请：Certbot

### 安装

Debian / Ubuntu：

```bash
apt-get update && apt-get install -y certbot
```

其它发行版用发行版包或 [Certbot 官方说明](https://certbot.eff.org/)。

### 方式 A：webroot（推荐，不停 Nginx）

前提：`location /.well-known/acme-challenge/ { root /usr/share/nginx/html; }` 已配置，且宿主机 `html` 已挂进容器。

```bash
BASE=/opt/nginx-gateway

certbot certonly --webroot \
  -w "$BASE/html" \
  -d example.com -d www.example.com \
  --email you@example.com \
  --agree-tos --non-interactive
```

成功后宿主机上会有：

```text
/etc/letsencrypt/live/example.com/fullchain.pem
/etc/letsencrypt/live/example.com/privkey.pem
```

`live/` 下本身是软链，指向 `archive/` 里带版本号的文件，这是 Certbot 正常结构。

### 方式 B：standalone（需短暂释放 80）

校验期要由 Certbot 自己听 80：

```bash
docker stop nginx-gateway

certbot certonly --standalone \
  -d example.com -d www.example.com \
  --email you@example.com \
  --agree-tos --non-interactive

docker start nginx-gateway
```

适合还没配好 webroot、或临时排障。生产更推荐方式 A。

### 子域很多时：通配符证书

`*.example.com` **必须 DNS-01**（改 TXT 记录），不能用 HTTP-01。流程因 DNS 厂商而异，可用 Certbot 的 DNS 插件或手动加 TXT。通配符证一份挂到所有子域 `ssl_certificate` 路径即可，免去每子域签一张。

主域 + `www` 的普通证书**不能**覆盖任意子域；子域要单独签，或上通配符。

## 怎么挂进 Docker Nginx（避开软链坑）

### 错误做法

在宿主机执行：

```bash
ln -s /etc/letsencrypt/live/example.com/fullchain.pem \
  /opt/nginx-gateway/certs/example.com/fullchain.pem
```

宿主机上 `ls` 看起来正常，但容器只挂了 `certs/`，**跟不到** `/etc/letsencrypt`，容器内 fopen 失败，典型日志：

```text
cannot load certificate ".../fullchain.pem": BIO_new_file() failed ... No such file or directory
```

`cp` 时若提示 *are the same file*，说明目标已是指向 Let’s Encrypt 的软链，需要先删再拷实体。

### 正确做法：拷贝实体文件

```bash
BASE=/opt/nginx-gateway
mkdir -p "$BASE/certs/example.com"

rm -f "$BASE/certs/example.com/fullchain.pem" \
      "$BASE/certs/example.com/privkey.pem"

# -L：顺着软链复制真实内容
cp -L /etc/letsencrypt/live/example.com/fullchain.pem \
  "$BASE/certs/example.com/fullchain.pem"
cp -L /etc/letsencrypt/live/example.com/privkey.pem \
  "$BASE/certs/example.com/privkey.pem"

chmod 644 "$BASE/certs/example.com/fullchain.pem"
chmod 600 "$BASE/certs/example.com/privkey.pem"

# 确认为普通文件，不是 -> 
ls -la "$BASE/certs/example.com/"

docker exec nginx-gateway ls -la /etc/nginx/certs/example.com/
docker exec nginx-gateway nginx -t && docker exec nginx-gateway nginx -s reload
```

备选：把 `/etc/letsencrypt` 只读挂进容器，并把 `ssl_certificate` 改成容器内 `/etc/letsencrypt/live/...` 路径。两种选一种，团队统一即可；拷贝法对「只暴露 certs 目录」更直观。

### Nginx 里怎么写

```nginx
ssl_certificate     /etc/nginx/certs/example.com/fullchain.pem;
ssl_certificate_key /etc/nginx/certs/example.com/privkey.pem;
ssl_protocols       TLSv1.2 TLSv1.3;
```

## 申请后怎么验

在服务器：

```bash
curl -sSI http://example.com/ | head -15
# 期望：301，Location: https://...

curl -sSI https://example.com/ | head -15
# 期望：200

echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -issuer -subject -dates
# 期望：issuer 含 Let's Encrypt，subject 含你的域名
```

服务端已是 Let’s Encrypt，浏览器仍显示「不安全」时，优先怀疑：

- 实际打开的是 `http://`（看是否未跳转或书签仍是 http）  
- 以前点过「继续访问」自签，站点数据未清：无痕窗口或重置该站权限后再开 `https://example.com`

## 自动续期

Certbot 安装后通常已有定时任务（systemd timer 或 cron）。续期成功后，**还要把新文件拷进网关目录并 reload**，否则容器仍读旧拷贝。

```bash
mkdir -p /etc/letsencrypt/renewal-hooks/deploy

cat > /etc/letsencrypt/renewal-hooks/deploy/copy-certs-nginx.sh <<'EOF'
#!/bin/sh
set -e
BASE=/opt/nginx-gateway
DOMAIN=example.com

rm -f "$BASE/certs/$DOMAIN/fullchain.pem" "$BASE/certs/$DOMAIN/privkey.pem"
cp -L "/etc/letsencrypt/live/$DOMAIN/fullchain.pem" "$BASE/certs/$DOMAIN/fullchain.pem"
cp -L "/etc/letsencrypt/live/$DOMAIN/privkey.pem"   "$BASE/certs/$DOMAIN/privkey.pem"
chmod 644 "$BASE/certs/$DOMAIN/fullchain.pem"
chmod 600 "$BASE/certs/$DOMAIN/privkey.pem"

docker exec nginx-gateway nginx -s reload
EOF

chmod +x /etc/letsencrypt/renewal-hooks/deploy/copy-certs-nginx.sh
```

干跑续期（不强制刷新未到期证书时用 `certbot renew`；要测钩子可用）：

```bash
certbot renew --dry-run
```

Let’s Encrypt 证书有效期约 90 天；定时任务一般会在到期前自动续。邮箱保持有效，便于接收到期提醒。

## 小结

| 步骤 | 要点 |
| --- | --- |
| 申请 | DNS 就绪；优先 `certbot certonly --webroot` |
| 挂载 | 拷贝实体到容器可见目录，禁止「只软链到宿主机 /etc/letsencrypt」 |
| 校验 | `curl` + `openssl` 看跳转与 issuer |
| 续期 | `renewal-hooks/deploy` 里再拷贝 + `nginx -s reload` |
